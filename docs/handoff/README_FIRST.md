# LeaseRadar（铺讯）开发交接包

版本：v1.0 · 2026-10-10。名称为工作名，未核验商标或仓库名称。

## 先看什么

1. `01_TECHNICAL_REPORT.md`：完整产品需求、技术架构、数据模型、算法、部署与真实试用方案。
2. `02_IMPLEMENTATION_PLAN.md`：阶段任务、依赖、验收与比赛实验。
3. `03_CODEX_START_PROMPT.md`：直接复制到 Codex 的启动指令。
4. `AGENTS.md`：放在项目根目录的开发约束。
5. `examples/subscription.example.yaml`：订阅需求示例，值均为设计示例。
6. `examples/source.example.yaml`：来源配置模板，无未经验证的选择器或接口。

## 项目目标

让门店拓展人员更早发现符合条件的招租公告，减少逐网站刷信息、重复整理和错过报名；多网站整合与比价为候选跟进服务。

本包是开发规格与计划，不是已实现软件。真实网站接入、消息通道和试用结果均需实际验证。负责人提供需求不代表企业官方合作。

## 本次交付范围

先做温州商铺：公开来源接入、持续监测、结构化与证据、去重、条件匹配、网页及配置后的外部通知、统一比价、跟进记录、来源健康监控。分阶段扩展，不能只完成静态看板。

## 最短开始方式

解压本包；在新的代码目录放入 AGENTS.md 和其余文档；把启动指令交给 Codex。若已有 AgentTwin 仓库，请另建 LeaseRadar 目录，不覆盖已有工程。

## 需要在试用前补齐的信息

- 负责人真实的筛选条件、额外来源、消息接收渠道和试用人员。
- 一台能持续运行的服务器及域名/HTTPS配置。
- 外部通知凭据；AI API密钥可选，费用由预算配置控制。
- 官方截止日期及比赛原文评分要求。本包使用前文提供的30/30/20/20分项规划，未重新读取原始评分截图。

缺少这些信息不阻塞离线开发，但不得把示例值当作负责人实际要求，也不得把未配置通知称为已送达。
